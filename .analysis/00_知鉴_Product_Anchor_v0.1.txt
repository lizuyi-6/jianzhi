North Star
100 个回答，不该只剩一个 AI 答案。知鉴降低理解大量真人经验的阅读成本，但不替用户做最终判断。
1. 一句话定义
在知乎的高经验依赖型问题中，知鉴从真人回答中恢复“经验 - 条件 - 分歧 - 来源”的结构，为当前用户构造一组最少但足够多元、可回到原文验证的阅读集合。

3. 不可破坏的 8 条产品不变量
不把多回答问题压缩成一个“综合建议”；知鉴的输出至少保留互不替代的真人视角。
不输出“所以你应该……”式最终人生建议，也不输出选择概率、胜率或适用度百分比。
每一个关键 AI 判断必须有原文依据；没有证据就是 Unknown，不允许补全作者背景。
相似条件只表示“可比较”，不表示“正确”“成功概率更高”或因果关系。
只处理当前 Question 所需的局部条件，不建立长期人格画像或跨问题用户标签。
只要存在条件相近但选择不同的高质量经验，Reading Set 必须至少保留一条反向经验。
知鉴不替代知乎默认公共排序；它只构造一个“先读这几篇”的临时阅读集合。
AI 的中间结构可以被用户查看、质疑和修改；系统必须允许弃权与不足状态。
4. 黄金路径锚点
Question 页  -> 点击「按我的情况看」  -> 大家真正分歧在哪？（2-4 个条件）  -> 用户确认「你的情况」  -> 3 席 Reading Set  -> 打开原回答 + 阅读提示 + 原文依据  -> 修改一个条件，Reading Set 发生可解释变化
完成定义
一次使用完成的标志不是“AI 给出了答案”，而是用户在 30 秒内知道哪几篇值得先读、为什么值得读、哪些地方不能直接照搬。

6. 变更规则
任何新增功能先回答：它是否让用户更快理解“哪些真人经验可比较”，还是只是让产品更像通用 AI 助手？
触碰 8 条产品不变量的变更，必须升级版本并同步修改 PRD、Constraints 与 AI/Data Contract。
MVP 阶段允许调整文案、视觉和实现细节；不允许改变赛道、本质、入口、三席 Reading Set 与“不做最终建议”的边界。
若官方 API 数据 Gate 未通过，允许替换数据入口或 Pivot；不允许用未授权批量爬取或模型补全去伪造数据可行性。
5 秒自检
如果一个新成员只能记住一句话：知鉴不是替用户回答，而是让用户知道“现在最值得先读哪几段真人经验，以及为什么”。
